# 홍보 사이트 개발 WBS

> 근거: 차장님 검토 회의 결과 (변경 계획 6건 · 서버 및 DB 구조 · 운영진 글 작성 방식)
> 날짜를 정하지 않는다. 앞 작업이 끝나는 대로 다음 작업을 이어서 진행한다.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목표 | 차장님이 만든 정적 페이지를 그대로 쓰면서 ① 디자인·문구를 다듬고 ② 운영진이 관리자 페이지에서 게시판형 글을 올리도록 만든다 |
| 구성 | 화면 GitHub Pages · 관문 Apps Script 웹앱 · 데이터 Google Sheets · 사진·첨부 Google Drive (아카이빙 사이트와 같은 구성, **시트·관문은 아카이빙과 분리**). 방문자는 관문을 거치지 않고, 저장 시 관문이 발행한 `data/posts.json`을 읽는다 |
| 관리 범위 | 공지사항 · 언론홍보 · 갤러리 · 메인 소식 목록 · 표지 사진 등 **게시판형만**. 사업소개·프로그램 등 고정 문구는 HTML에서 개발자가 고친다 |
| 로그인 | 접근코드 (추후 구글 로그인으로 바뀔 수 있음 → 인증부를 따로 떼어 교체하기 쉽게 만든다) |
| 사진 표시 | 공개 글에 첨부된 파일만 "링크가 있는 사용자" 공개. 사진은 사이트 안에서 표시하고 확대도 사이트 안에서 한다 |
| 첨부파일 | hwp · docx · pdf 등, 파일당 100~200KB. 방문자가 내려받을 수 있다 |
| 기존 관리 화면 | 차장님이 만든 간이 CMS(`admin.html` · `cms.js` · `edit.js` · `edit.css` · `content.json`)는 `_legacy/`에 이름 뒤 `1`을 붙여 원본 그대로 보관하고 사용하지 않는다 |
| 배포 | 작업 브랜치 `home/parkjiheon`에서 개발 → `main` 병합 시 반영. **배포 중인 사이트는 닫지 않는다** |

## 4. 진행 순서

```
0 준비 → 1 설계 → 2 디자인·문구 ──→ M2 디자인 1차 배포
                 └→ 3 관문 → 4 관리자 페이지 ┐
                          └→ 5 방문자 화면 ──┴→ 6 테스트·배포 (M5)
```

- 2단계는 관문과 무관하므로 끝나는 대로 먼저 배포할 수 있다.
- `자료 대기` 작업은 순서를 막지 않는다. 자료가 오면 그때 끼워서 처리한다.
- 4단계는 관문(3.4~3.8)이 동작해야 진행할 수 있다. 5단계는 `data/posts.json` 모양(`sheet-schema.md` 3절)만 있으면 되므로 시험용 파일로 관문보다 먼저 시작할 수 있다.
