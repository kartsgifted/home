## 3. 시스템 구성

| 항목 | 결정 | 이유 |
|---|---|---|
| 구성 | 화면 GitHub Pages · 관문 Apps Script 웹앱 · 데이터 Google Sheets · 사진·첨부 Google Drive | 아카이빙과 같은 구성. 운영 경험과 코드를 재사용 |
| 아카이빙과 분리 | 시트 · 관문 · 드라이브 폴더를 **새로 만든다** | 아카이빙 시트에는 학생 실명이 있음. 공개 사이트와 같은 관문을 쓰면 사고 범위가 커짐 |
| 방문자 목록 전달 | **저장 시 정적 JSON 발행.** 운영진이 저장하면 관문이 공개 글을 `data/posts.json`으로 만들어 GitHub API로 이 저장소에 커밋하고, 방문자 화면은 그 파일을 읽는다 (2026-10-13 사용자 결정) | 아카이빙 실측상 관문 요청 한 번이 1~3초라 홍보 사이트 목록이 늦게 뜸. 방문자가 관문을 거치지 않으므로 Apps Script 동시 실행 한도에도 걸리지 않음 |
| 발행 시점 | 저장 · 삭제 · 공개 전환을 처리한 **그 요청 안에서** 바로 발행. 발행만 실패하면 저장은 유지하고 관리자 화면에 [다시 반영] 버튼을 보인다 | 트리거로 모아 발행하는 방식보다 단순하고, 운영진이 반영 성공 여부를 바로 알 수 있음 |
| 반영 지연 | 발행 후 GitHub Pages 빌드까지 약 1~2분. 관리자 화면에 안내한다 | GitHub Pages 구조상 피할 수 없음 |
| 관리 요청 시간 | 실측(2026-10-13): 로그인 · 목록 약 3~6초, 업로드 5~9초, 저장 · 삭제(발행 포함) 9~11초. 관리자 화면은 처리 중 표시와 중복 클릭 방지를 둔다. 업로드는 드라이브 저장을 잠금 밖에서 해 **사진 3장씩 동시에** 올린다 | 시트 읽기 · 드라이브 공유 · GitHub 커밋(2회 호출)이 한 요청에 모두 들어감 |
| 빌드 한도 | GitHub Pages(브랜치 배포)는 시간당 빌드 10회의 소프트 한도가 있다. 넘었을 때 지연되는지 건너뛰는지는 **확인 필요** | 첫 입력 때처럼 짧은 시간에 여러 번 저장하면 걸릴 수 있음 |

| 발행 대상 브랜치 | Script Properties 값으로 정한다. 개발 중에는 시험용 브랜치 `data-test`였고, **2026-10-14부터 `main`** (사용자가 바꿈, 첫 발행 11:48). 그래서 main에는 관문 커밋(`data/posts.json`)이 수시로 생긴다. **배포는 `git fetch origin` → `git merge origin/main` → 작업 브랜치 push → `git push origin home/parkjiheon:main` 순서로 하고, main에 강제 push하지 않는다** (공지 목록이 지워짐) | 시험 글이 작업 브랜치와 운영 사이트에 섞이지 않게 함 |

## 4. 게시판

| 항목 | 결정 | 이유 |
|---|---|---|
| 게시판 종류 | **공지사항 · 갤러리** 두 개 | |
| 공지 분류 | 공지 · 워크숍 · 심화과정 (2026-10-14 「아카이브」 삭제 — 아카이브 연계 삭제에 따름. 처음에는 `news.html` 예시 기준 4개). 시트 「설정」에서 바꿀 수 있게 한다 | 분류가 늘거나 줄어도 코드를 고치지 않게 함 |
| 메인 소식 목록 | 메인 맨 아래는 **「공지사항」 칸 하나**(공지 최신 3개)와 연락처만 둔다. 「아카이브」 칸은 없애고 공지사항 칸을 넓힌다 (2026-10-13 변경, 사용자 결정. 처음에는 분류 「아카이브」 공지를 모은 칸이 따로 있었음) | 메인에 아카이브 칸을 따로 보여 줄 필요가 없다고 판단 |
| 공지 본문 형식 | **일반 글 + 자동 링크 + 정해진 서식 3가지** (2026-10-13 변경, 사용자 결정. 처음에는 서식 없음). 운영진이 고른 부분에만 `**굵게**` · `{강조:청록}` · `{빨강:빨강}`을 쓴다. 관리자 화면에 서식 버튼과 미리보기가 있다. 글꼴 · 크기 · 그 밖의 색은 없음 | 운영진이 마감일 · 주의 문구를 강조할 일이 있음. 색을 사이트 색 두 가지로 묶어 디자인이 깨지지 않게 함. 표시는 `assets/js/board.js` 한 곳에서 DOM으로 만들어(innerHTML 없음) 관리자 미리보기와 방문자 화면이 항상 같음. 외부 라이브러리 없음 |
| 공지 구성 | 사진 · 글 · 첨부파일은 **각각 선택.** 비어 있는 칸은 화면에 나오지 않는다 | 포스터만 있는 공지, 글만 있는 공지 모두 같은 화면으로 처리 |
| 사진 위치 | 기본은 사진 → 글 → 첨부. 글마다 「사진을 글 아래에」를 고를 수 있다 (사용자 결정) | 사진을 글 중간에 넣는 것은 편집기가 필요해 하지 않음 |
| 사진 링크 | 글마다 「사진을 누르면 이동할 링크」 칸을 둔다 | 포스터를 누르면 신청 폼으로 가는 발레축제 방식 |
| 첨부파일 | 이름 · 크기를 목록으로 보여주고 누르면 바로 내려받는다. 다운로드 횟수는 세지 않는다 | 정적 JSON 방식에서는 횟수를 셀 수 없음 |
| 상단 고정 | 공지마다 「상단 고정」 선택 가능. 고정 글이 먼저, 나머지는 게시일 최신순. 방문자 화면(news · 메인)에는 **순서만 위로 하고 따로 표시하지 않는다** (2026-10-14 사용자 결정) | 확인 필요 — 사용 여부. 쓰기로 하면 표시를 더할 수 있음 |
| 내용 없는 공지 | 본문 · 사진 · 첨부가 모두 없는 공지는 목록(news · 메인)에 **보이되 눌러도 이동하지 않는다.** 마우스를 올렸을 때의 반응(배경색 · 손가락 커서)은 다른 글과 같다 (2026-10-14 사용자 확인. 처음 구현은 반응까지 없애 "죽은 줄"처럼 보였음). 무엇이든 채우면 자동으로 누를 수 있게 된다 (사용자 결정). 관리자 화면은 이런 공개 글을 저장할 때 확인 창으로 한 번 묻는다 (2026-10-14 사용자 결정. 처음에는 저장을 막아 기존 글의 제목도 고칠 수 없었음) | 비공개는 목록에서도 사라져 원하는 동작이 아님. 기존 글은 제목만 있어 눌러도 빈 글이 됨 |
| 갤러리 표시 | 목록에는 제목과 설명("2026.07 · 광주캠퍼스")만 보이고 게시일은 보이지 않는다. 최신 게시일이 먼저. **사진이 없는 앨범은 기본 그라디언트 칸으로 보이고, 마우스 반응(칸이 살짝 커짐)은 같되 눌러도 아무 일도 없다** (사용자 결정, 2026-10-14 반응 추가) | 기존 앨범은 날짜가 월까지만 있음. 사진을 받기 전에도 지금 사이트 모습을 유지 |
| 공개여부 | 공개 · 비공개. `data/posts.json`에는 공개만 들어간다 | 미리 써 두고 나중에 공개할 수 있게 함 |

| 글 상세 주소 | `news.html#notice/글ID` — 공지 탭 안에서 상세를 보여주고, 주소를 복사해 공유할 수 있다 | 페이지를 새로 만들지 않고 기존 탭 구조를 그대로 씀 |

## 5. 사진 · 첨부파일

| 항목 | 결정 | 이유 |
|---|---|---|
| 보관 | Google Drive 홍보용 폴더. **폴더는 공유하지 않는다** | |
| 방문자 표시 | 첨부 파일을 「링크가 있는 사용자 — 보기」로 공유하고, 사이트 안 `<img>`로 바로 불러온다 (사용자 결정 B) | 관문을 거쳐 base64로 보내면 사진 한 장에 수 초가 걸림 |
| 공유 시점 | **올리는 즉시 공유**하고, 글에서 빼거나 글을 삭제하면 공유를 끊고 휴지통으로 보낸다. 비공개 전환은 공유를 바꾸지 않는다 (2026-10-13 변경, 사용자 결정. 처음에는 "공개 글만 공유") | 공개 글만 공유하면 관리자 화면에서도 비공개 글의 사진이 보이지 않아 여러 날에 걸쳐 앨범을 만들 수 없음. 파일ID는 추측할 수 없는 33자라 공개된 적 없는 사진은 찾을 수 없음. **한 번 공개했던 사진은 예전 `posts.json` 이력에 ID가 남으므로, 확실히 내리려면 비공개가 아니라 삭제해야 한다** — 운영진 안내서(6.7)에 적는다 |
| 사진 주소 | 화면 코드 **한 곳**(`board.js`)에서만 만든다. 기본 `https://lh3.googleusercontent.com/d/{파일ID}=w{폭}` | 구글이 공식 보장하는 주소가 아님. 막히면 이 한 곳만 바꾼다 |
| 첨부 내려받기 | `https://drive.google.com/uc?export=download&id={파일ID}` — 드라이브 화면을 거치지 않고 내려받아짐. 파일명은 드라이브에 저장된 이름(원래 이름 유지) | 100~200KB 파일이라 바이러스 검사 확인 화면이 뜨지 않음 |
| 사진 축소 | 관리자 화면에서 올리기 전에 브라우저가 긴 변 1600px JPEG로 줄인다 | 업로드 · 표시 속도 |
| 저장소에 사진을 넣지 않는 이유 | 사진을 GitHub에 커밋하면 지워도 커밋 이력에 남는다(공개 저장소). 학생 사진 삭제 요청에 응할 수 없게 됨 | |
| 허용 형식 · 용량 | `sheet-schema.md` 6절 | |
